# Telegram-бот «Свой ритм»

Две функции: тест с выдачей программы и уведомления владельцу о регистрациях. Уведомления о сайте уже использует `/api/lead`; этот процесс добавляет тест в Telegram и уведомления о регистрациях в боте.

## Подключение

1. В Telegram открыть https://t.me/BotFather, отправить `/newbot`, задать имя и уникальный username с окончанием `bot`. Сохранить токен конфиденциально. Не отправлять его в чат помощника, Git или исходники.
2. В закрытом `site/.env.local` или защищённых настройках окружения задать `TELEGRAM_BOT_TOKEN`. Не использовать публичный `NEXT_PUBLIC_` префикс. Имя переменной — не сам секрет.
3. Из `site/` выполнить `npm run setup:local`, затем `npm run bot:check`. Проверка делает только `getMe` и `getWebhookInfo`, не рассылает сообщения и не удаляет существующий webhook. Если у бота уже есть webhook, решить миграцию отдельно.
4. Запустить `npm run bot`. Бот использует long polling: публичный веб-адрес и HTTPS webhook не нужны. Требуется исходящий HTTPS-доступ к api.telegram.org и один работающий процесс на токен. Сайт запускается отдельным процессом.
5. Открыть своего бота, нажать Start, отправить `/id`. Свой числовой chat_id сохранить в `TELEGRAM_CHAT_ID` — это адрес получения уведомлений. Перезапустить бота и сайт, чтобы оба процесса прочитали переменную.
6. Пройти тест со своим контактом, подтвердить согласие, убедиться в получении программы и уведомления. Для первой проверки использовать свои данные или отдельную тестовую среду; синтетические тесты не доказывают доставку в Telegram.

## Как проходит тест

- Только личный чат; в группе контакты не запрашиваются
- Выбор нескольких целей, рацион, активность, ограничения
- Имя; собственный телефон через Telegram contact; username берётся из аккаунта (если его нет, бот просит настроить)
- Отдельное согласие; только затем сохранение в SQLite и выдача программы
- Лекарства, беременность, хронические заболевания и несовершеннолетие исключают автоматические варианты продуктов
- Нет диагнозов, определения дефицитов и назначенных дозировок

Команды: `/start`, `/privacy`, `/cancel`, `/id`. Отказ от согласия и `/cancel` очищают незавершённую сессию. Сессии в памяти, срок бездействия 30 минут с очисткой при следующих обновлениях; после перезапуска начать заново. Программа не сохраняется в отдельный личный кабинет — остаётся в истории чата. Изменённые/устаревшие callback-кнопки не меняют текущую сессию.

В базе сохраняются контакты и факт согласия; ответы теста и история переписки в неё не записываются. Но сами сообщения обрабатываются Telegram и остаются в истории чата. `/privacy` честно сообщает об этом. До публичного запуска владелец дополняет политику полными реквизитами, сроками и условиями обработки.

## Постоянная работа

Для 24/7 нужен сервер с Node.js24, постоянным диском и менеджером процессов (например systemd). Хранить `.env.local`, файл SQLite и polling-offset только в закрытом каталоге; резервировать базу. Не запускать второй `npm run bot` с тем же токеном. Файл `telegram-offset.json` хранится рядом с SQLite, чтобы не читать всю историю после перезапуска. Работающий процесс не переживает выключение облачной среды — сохранённые инструкции не равны круглосуточному запуску.

`npm ci` должен установить и devDependencies: исполняемый файл `tsx` используется для bot/run.ts. Токен читается при старте; при смене перезапустить процесс. Логи не должны содержать токен, тела запросов, ответы теста или контакты. Код ошибок Telegram выводится без URL с токеном. При 401 или 409 процесс завершается с понятной ошибкой. Уведомление не гарантирует ровно одну доставку при сбоях сети; сбой уведомления не отменяет уже сохранённую регистрацию.

## Проверки

`npm test` включает 9 серверных и bot-тестов. Telegram API в тестах подменён: реальной отправки и получения нет. Проверены полное прохождение, отсутствие сохранения до согласия, отказ, чужой контакт, повторные кнопки, сбой базы, истечение сессии, закрытые группы и отсутствие токена в ошибках. Живые getMe, получение updates и доставка требуют настоящего токена.

## Переход с сайта и учёт Start

После регистрации сайт получает подписанную ссылку `https://t.me/Tolbuhina_bot?start=lead_...` и открывает её через 8 секунд. Есть кнопка немедленного перехода и отмена. Ссылка действует 7 дней, содержит только идентификатор заявки, срок и подпись — без телефона и ответов. Start засчитывается только для Telegram username, указанного в регистрации (регистр букв не важен). Пересланная ссылка не даёт менять привязку другого пользователя.

Для существующей базы выполнить `supabase/migrations/20261020_telegram_tracking.sql`. В leads появятся telegram_started_at, telegram_user_id и telegram_chat_id. Новые регистрации работают и до миграции; но Start до неё не сможет подтвердиться. Это отметка запуска, не подтверждение пожизненной подписки. Блокировка бота отдельно не отслеживается.

### Vercel webhook, без постоянного polling-процесса
1. В Vercel задать TELEGRAM_WEBHOOK_SECRET — отдельную случайную строку из букв, цифр, `_`/`-`, 32–256 символов, тип Secret. Значение не публиковать. TELEGRAM_BOT_TOKEN уже должен быть настроен.
2. Указать SITE_URL основного HTTPS-адреса сайта. Если он не указан, используется системный VERCEL_PROJECT_PRODUCTION_URL. Webhook должен смотреть на основной доступный Production-адрес, а не защищённый Preview.
3. Применить новую Production-сборку. Если запущен npm run bot, остановить его: polling и webhook вместе не работают.
4. Открыть основной сайт с путём `/connect-telegram`, ввести TELEGRAM_WEBHOOK_SECRET в защищённую форму и нажать «Подключить». Токен из браузера не передаётся — берётся сервером из Vercel.
5. Пройти тест, перейти в бот и нажать Start. Проверить telegram_started_at в leads. Пустое поле означает «запуск не подтверждён», не «точно не заходил».

Webhook проверяет `X-Telegram-Bot-Api-Secret-Token`, сохраняет привязку при Start и отвечает в Telegram. `/id` сообщает свой chat_id. Повторные доставки не меняют уже записанное время и не перепривязывают заявку к другому Telegram ID. Чужое существующее webhook-подключение не заменяется без отдельного решения. Полный повторный опрос внутри бота остаётся функцией отдельного polling-процесса; минимальный Vercel webhook обслуживает связку с заявками сайта.

Живое подключение webhook и миграция базы требуют действий в аккаунтах владельца; локальные тесты Telegram API используют подмену и не доказывают доставку.
