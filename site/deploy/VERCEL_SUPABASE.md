# Vercel + Supabase

Этот режим заменяет SQLite для сайта. Процесс Telegram long polling размещается отдельно; бессрочный npm run bot не работает внутри обычной Vercel Function.

## Supabase
1. Открыть проект → SQL Editor → выполнить `/workspace/Tolbuhina/supabase/leads.sql`. Не создавать публичные политики доступа к таблице leads.
2. В настройках API проекта скопировать Project URL и серверный Secret key (sb_secret_…; для старого проекта service_role). Не anon/publishable. Ключ не отправлять в чат и не помещать в NEXT_PUBLIC_ переменные.

## Vercel
Импортировать **свой** репозиторий vimoxx26-hue/Tolbuhina (код сайта должен быть сохранён туда; upstream website-designer-agent не использовать). Root Directory: `site`. Framework: Next.js. Node.js: 24.x. Install: npm ci. Build: npm run build.

Settings → Environment Variables, для нужных Production/Preview окружений:

| Переменная | Значение |
| --- | --- |
| LEAD_STORAGE | supabase |
| SUPABASE_URL | реальный https://PROJECT.supabase.co |
| SUPABASE_SECRET_KEY | серверный секрет проекта |
| REGISTRATION_SECRET | отдельный случайный секрет длиной не меньше 32 символов |
| SITE_OWNER_NAME | Виталий (дополнить полными данными оператора) |
| SITE_OWNER_CONTACT | https://t.me/Vimoxx26 |
| SITE_URL | точный HTTPS-адрес текущего окружения |
| TELEGRAM_BOT_TOKEN | токен Tolbuhina_bot, если нужны уведомления |
| TELEGRAM_CHAT_ID | числовой ID получателя, если нужны уведомления |

LEAD_DB_PATH в этом режиме не нужен. REGISTRATION_SECRET создаётся локально менеджером паролей или `node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"` на вашем компьютере. Его значение вводится только в закрытые настройки. Не копировать пример ключа из документации. SITE_URL для Preview не должен указывать на другой домен Production, иначе Origin-проверка отклонит регистрацию; для разных Preview-доменов можно не задавать SITE_URL до закрепления адреса (canonical/sitemap тогда не настроены).

После изменения переменных выполнить Deployments → Redeploy, чтобы изменения применились. Привязка аккаунтов через Vercel Marketplace необязательна: этот сайт использует серверный REST API с явно заданными именами переменных. Если интеграция создала NEXT_PUBLIC_SUPABASE_URL, добавить SUPABASE_URL отдельно; серверный ключ никогда не делать NEXT_PUBLIC_.

## Проверка
- Проверка в подготовленном окружении с этими закрытыми переменными: `npm run supabase:check` — только чтение схемы, без чтения контактов и без записи
- По публичному адресу пройти тест, зарегистрировать собственные тестовые данные и проверить строку в Table Editor → leads
- Убедиться, что после регистрации открывается программа, без cookie /api/program отказывает
- Если включён Telegram, проверить отдельную доставку владельцу. Запись в базе и уведомление — разные проверки
- Политика обработки контактов остаётся черновиком до уточнения владельца, сроков и размещения данных

Для владельца в России до сбора реальных контактов проверить применимость выбранного расположения базы и хостинга требованиям обработки персональных данных. Этот документ не подтверждает пригодность иностранного региона.
