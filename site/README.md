# Свой ритм — посадочная подбора витаминов

Next.js 16 / React 19 / TypeScript. Русскоязычная страница, пятишаговый опрос, регистрация по имени + телефону + Telegram и защищённая программа на сайте. Рабочее название «Свой ритм» предложено как часть оформления.

## Запуск

Node.js 24, npm 11. Из `/workspace/Tolbuhina/site`:

```sh
npm_config_cache=/workspace/.npm-cache npm ci
npm run dev -- --hostname 0.0.0.0
```

Сервер нужен в каждой новой сессии. Производственный запуск: `npm run build`, затем `npm run start -- --hostname 0.0.0.0`. Локальный запуск не является публикацией.

## Реальные регистрации

По умолчанию используется встроенная SQLite на постоянном диске сервера. Отдельный аккаунт базы не требуется.

```sh
npm run setup:local
npm run dev -- --hostname 0.0.0.0
```

`setup:local` создаёт закрытый каталог `../.data`, случайный ключ подписи и локальные настройки в `.env.local`. Существующие значения сохраняются. Настройки и база исключены из Git. Не печатать `.env.local`, не отправлять ключи в чат и не включать базу с контактами в архив исходников.

Перед публичным запуском разместить сайт с постоянным диском на российском сервере и проверить условия обработки данных. Для SQLite Vercel и другие платформы с временным диском не подходят. Не размещать файл базы в `public/`; делать защищённые резервные копии и проверять восстановление. При переезде копируются база и закрытый ключ, не процессы.

Владелец: Виталий, Россия, @Vimoxx26. Дополнить `/privacy` полными сведениями об операторе, сроками хранения и условиями передачи данных. Политика пока черновик. В `SITE_URL` задать итоговый HTTPS-адрес, затем пересобрать сайт: это включит корректный sitemap, canonical и проверку точного Origin.

Telegram-уведомления необязательны: если нужны, настроить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в закрытых переменных сервера, предварительно проверить условия передачи контактов. Без настройки данные сохраняются только в базе, а результат всё равно открывается. Успешное сохранение обязательно для выдачи доступа.

Альтернативно доступен Supabase: `LEAD_STORAGE=supabase`, `SUPABASE_URL`, настоящий серверный `SUPABASE_SECRET_KEY`; выполнить `../supabase/leads.sql`. Для локальной подписи нужен настоящий `REGISTRATION_SECRET` (не заглушка сетевого прокси). Проверить размещение базы до приёма персональных данных в России. Браузеру серверные ключи не передаются.

Это регистрационная форма, а не полноценная система учётных записей: контакты не подтверждаются SMS/Telegram; регистрация даёт cookie доступа на сутки. Если потребуется верификация номера, добавить OTP отдельно. Ответы о здоровье не записываются в базу и не отправляются в уведомления. Не включать журналирование тел запросов `/api/program`. Согласие на рекламу отсутствует.

## Проверки

```sh
npm run lint
npm test
npm run build
npm run test:e2e
```

`test:e2e` запускает собственный Next dev на 3100. По умолчанию тест использует настоящую временную SQLite и удаляет её после проверки. Все контакты синтетические. E2E_STORAGE=supabase включает дополнительный режим с имитацией REST-базы. Нужен Chromium (`CHROMIUM_PATH` или `/usr/bin/chromium`). Использует только синтетические контакты и тестовый ключ, не реальные внешние сервисы. Проверяет четыре размера экрана, регистрацию, cookie-защиту, выдачу программы и ограничение рекомендаций. Сохраняет изображения в `../artifacts/`.

Ограничение запросов в памяти процесса: для публичного трафика добавить общую защиту на уровне прокси/WAF и контроль злоупотреблений. Куки не доказывает личность пользователя. Для удаления данных предусмотрен контакт владельца; автоматического кабинета удаления нет.

Товары проверены по источнику 20 октября 2026, ссылки и противопоказания — `lib/catalog.json` и `../content/research.md`. Тест не диагностирует дефициты и не назначает дозировки/курсы. Результат — информационный план; при ограничениях продукты не предлагаются. Каталог следует актуализировать до кампании.
